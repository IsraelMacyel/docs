## Arquivo de configuração? O que é isso? 🤔
O arquivo de configuração é um arquivo que contém os parâmetros da sua aplicação, como o arquivo principal, memória, versão e outros parâmetros. Esse arquivo é utilizado para configurar e fazer o deploy da sua aplicação na plataforma VirtusCloud.

## Criando o arquivo de configuração
É muito simples criar o arquivo de configuração: basta criar um arquivo com o nome `virtuscloud.app` ou `virtuscloud.config` e inserir os parâmetros de configuração dentro dele.

<Steps>
    <Step title="Selecione a extensão">
        O arquivo de configuração pode ter duas extensões: **.app** ou **.config**. Você pode escolher a extensão que preferir. Dica: use **.app** para ajudar a promover a VirtusCloud (virtuscloud.app). 😂
        <Info>No **macOS**, recomendamos usar a extensão **.config**.</Info>
        <Warning>Atenção: **.app** ou **.config** é a **extensão do arquivo**, **não o nome**.</Warning>
    </Step>
    <Step title="Crie o arquivo">
        Crie um arquivo com a extensão selecionada e insira os parâmetros de configuração dentro dele.
    </Step>
</Steps>

## Parâmetros de configuração
Abaixo você pode ver os parâmetros de configuração que podem ser usados no seu arquivo de configuração.

<Steps>
    <Step title="MAIN [*]" icon="file">
        O parâmetro **MAIN** é usado para definir o arquivo principal da sua aplicação.
        ```systemd Exemplo:
        MAIN=index.js
        ```
        ```systemd Também suporta subdiretórios.
        MAIN=src/loaders/index.js
        ```
        <Info>Este parâmetro tem no máximo **32 caracteres**.</Info>
        <Info>Esta configuração é **IGNORADA** se você usar o parâmetro START.</Info>
    </Step>
    <Step title="MEMORY [*]" icon="memory">
        O parâmetro **MEMORY** é usado para definir a quantidade de memória que sua aplicação usará na plataforma VirtusCloud.
        ```systemd
        MEMORY=256
        ```
        <Info>O valor é em megabytes (MB).</Info>
        <Note>A memória mínima para um bot é **256MB** e para um site é **512MB**.</Note>
    </Step>
    <Step title="VERSION [*]" icon="arrow-up-9-1">
        O parâmetro **VERSION** é usado para definir a versão da sua aplicação.
        ```systemd
        VERSION=recommended
        ```
        <Info>Para cada linguagem há uma versão diferente, veja a tabela abaixo.</Info>
        | Linguagem                | Versão `recommended`   | Versão `latest`  |
        | ------------------------ | ---------------------- | ---------------- |
        | JavaScript [Node.js]     | 22.18.0                | 24.5.0           |
        | Python                   | 3.13.6                 | 3.13.6           |
        | Java                     | JDK 23                 | JDK 25           |
        | Elixir                   | 1.18.4                 | 1.18.4           |
        | Rust                     | 1.89.0                 | 1.89.0           |
        | PHP                      | 8.4.11                 | 8.4.11           |
        | Go                       | 1.24.6                 | 1.24.6           |
        | C#                       | 9.0.1                  | 9.0.1            |
        | HTML/CSS                 | Build 10-02-2025       | Build 10-02-2025 |

        <Tip>Recomendamos usar a versão `recommended`, pois nossa equipe realizou testes extensivos em todas as versões recomendadas.</Tip>
    </Step>
    <Step title="DISPLAY_NAME [*]" icon="text">
        O parâmetro **DISPLAY_NAME** é usado para definir o nome da sua aplicação.
        ```systemd Exemplo:
        DISPLAY_NAME=Admin BOT
        ```
        <Info>Este parâmetro tem no máximo **32 caracteres**.</Info>
    </Step>
    <Step title="DESCRIPTION" icon="text">
        O parâmetro **DESCRIPTION** é usado para definir a descrição da sua aplicação.
        ```systemd Exemplo:
        DESCRIPTION=Este bot foi criado para ajudá-lo nas suas tarefas diárias.
        ```
        <Info>Este parâmetro tem no máximo **280 caracteres**.</Info>
    </Step>
    <Step title="AUTORESTART" icon="rotate">
        O parâmetro **AUTORESTART** é usado para definir se sua aplicação deve reiniciar automaticamente em caso de falha.
        ```systemd Exemplo:
        AUTORESTART=true
        ```
        <Info>Por padrão, este parâmetro é definido como `false`.</Info>
    </Step>
    <Step title="SUBDOMAIN" icon="globe">
        O parâmetro **SUBDOMAIN** é usado para definir o subdomínio do seu site.
        ```systemd Exemplo:
        SUBDOMAIN=meusite
        ```
        <Info>Este parâmetro tem no máximo **63 caracteres**.</Info>
        <Note>A URL do site será: meusite.virtusapp.cloud</Note>
    </Step>
    <Step title="START" icon="play">
        O parâmetro **START** é usado para definir um comando de inicialização personalizado para sua aplicação.
        ```systemd Exemplo:
        START=npm run start
        ```
        <Info>Este parâmetro tem no máximo **256 caracteres**.</Info>
        <Info>Este parâmetro **ignora** o parâmetro MAIN, que é usado para unir os comandos de inicialização padronizados da VirtusCloud.</Info>
        <Info>Aplicações enviadas após 19 de junho de 2025 podem editar este campo sem precisar fazer upload novamente</Info>
    </Step>
</Steps>


## Exemplos de configuração para bots
Temos alguns exemplos de configurações para bots, veja alguns exemplos abaixo.

```systemd Este exemplo usa apenas os parâmetros obrigatórios. (configuração mínima)
MAIN=index.js
MEMORY=256
VERSION=recommended
DISPLAY_NAME=Robin bot
```

```systemd Este exemplo é um bot com todos os parâmetros.
MAIN=index.js
MEMORY=256
VERSION=recommended
DISPLAY_NAME=Robin bot
DESCRIPTION=Robin é um bot criado para ajudá-lo nas suas tarefas diárias.
AUTORESTART=true
```

```systemd Este exemplo usa todos os parâmetros e COMANDO DE INICIALIZAÇÃO PERSONALIZADO em um bot.
MAIN=index.js
MEMORY=512
VERSION=recommended
DISPLAY_NAME=Batman force
START=npm run start
```

## Exemplos de configuração para sites
Temos alguns exemplos de configurações para sites, veja alguns exemplos abaixo.

<Info>A URL do site será: meusite.virtusapp.cloud</Info>
```systemd Este exemplo usa todos os parâmetros e COMANDO DE INICIALIZAÇÃO PERSONALIZADO em um site.
MAIN=index.js
MEMORY=512
VERSION=recommended
DISPLAY_NAME=Meu site!
DESCRIPTION=Meu site é muito legal!
SUBDOMAIN=meusite
START=npm run build && npm run start
AUTORESTART=true
```

<Info>MAIN `next.config.js` usado apenas para o sistema reconhecer o projeto como um projeto JavaScript ou TypeScript (outro arquivo .ts/.tsx)</Info>
```systemd Exemplo de site Next.js.
MAIN=next.config.js
MEMORY=1024
VERSION=recommended
DISPLAY_NAME=Site Next.js
DESCRIPTION=Este site é construído com Next.js.
SUBDOMAIN=nextjs
START=npm run build && npm run start
AUTORESTART=true
```

## Reforçando os limites
Por razões de segurança e desempenho, há limites nos parâmetros de configuração, veja abaixo os limites de cada parâmetro.

| Parâmetro     | Limite de caracteres |
| ------------- | -------------------- |
| MAIN          | 32 caracteres        |
| DISPLAY_NAME  | 32 caracteres        |
| DESCRIPTION   | 280 caracteres       |
| START         | 256 caracteres       |
| SUBDOMAIN     | 63 caracteres        |
